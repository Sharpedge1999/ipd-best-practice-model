# ipd trace extension - XML contract (S0)

Status: 06 Nov 2026, version 1.1 (1.1: optional `ipd:trace` attributes `record` and `party`; one placement rule in section 4 - decisions.md S0-17; additive, namespace URI unchanged). Consumers: converter (B2), viewer (W1), validator (V1). Machine-readable descriptor: `contracts/ipd_moddle.json` (bpmn-moddle extension package).

## 1. Purpose

Every BPMN element that carries trace data in the spec (any trace field as defined in section 4: `src`, `req`, `binding`, `jurisdiction`, `deadline`, `draft`, `verify`, `record`, `party`) gets the same data twice (workflow_plan section 4):

1. as plain text in `bpmn:documentation` (human-readable in any modelling tool), format in section 5;
2. as structured XML in `bpmn:extensionElements/ipd:trace` (machine-readable for viewer and validator), format below.

Both are generated by the converter from the spec only. Hand edits of the XML are not allowed (GEN-01).

## 2. Namespace

| Item | Value |
|---|---|
| Namespace URI | `urn:ipd-best-practice:trace:1.0` |
| Prefix | `ipd` |
| Declaration | on `bpmn:definitions`: `xmlns:ipd="urn:ipd-best-practice:trace:1.0"` |

A breaking change requires a new URI (`...:trace:2.0`) and a new descriptor.

## 3. Elements and attributes

Attributes are unqualified (no prefix). All attribute values are strings in XML; `draft` is `true` or `false`.

| Element | Parent | Cardinality | Attributes / content | Spec source |
|---|---|---|---|---|
| `ipd:trace` | `bpmn:extensionElements` | 0..1 per BPMN element | `binding` (optional), `jurisdiction` (optional), `deadline` (optional), `draft` (optional), `record` (optional), `party` (optional) | element-level fields |
| `ipd:source` | `ipd:trace` | 0..n, spec order | `key` (required), `loc` (required), `page` (optional) | `src[]` items `{key, loc, page}` |
| `ipd:req` | `ipd:trace` | 0..n, spec order | `id` (required), e.g. `REQ-031` | `req[]` |
| `ipd:verify` | `ipd:trace` | 0..n, spec order | text content, one open item each, copied verbatim | `verify[]` |

Value domains:

- `binding`: `binding-law` \| `binding-ICH` \| `guidance` \| `best-practice` \| `verify-binding` (same enum as the spec and findings schemas).
- `jurisdiction`: space-separated list of `ICH`, `EU`, `US` in spec order, e.g. `"EU US"`.
- `deadline`: free text as in the spec, e.g. `"7 days"`; omit the attribute if the spec has no deadline or `none`.
- `draft`: write `draft="true"` only when the spec says `draft: true`; otherwise omit the attribute (absent = false). Viewer shows the DRAFT badge when `draft="true"`.
- `record`: free text copied verbatim from the spec field `record` (the record produced by the element); omit if absent or empty.
- `party`: verbatim party term(s) of the element's REQs, copied from the spec field `party`; several terms joined with `"; "`; omit if absent or empty.
- `key`: a key from `contracts/source_registry.yaml`.
- `loc`, `page`: copied verbatim from the spec (the spec copies them from the findings).

Child order inside `ipd:trace` is fixed: all `ipd:source`, then all `ipd:req`, then all `ipd:verify`. Attribute order on `ipd:trace`: `binding`, `jurisdiction`, `deadline`, `draft`, `record`, `party`. Fixed order keeps the output deterministic (B2 gate: identical sha256 on two runs).

## 4. Placement

- Rule: write `ipd:trace` (and the trace text of section 5) on an element whenever any trace field is present on its spec record. Trace fields: `src`, `req`, `binding`, `jurisdiction`, `deadline`, `draft`, `verify`, `record`, `party`. This applies to every element kind that can carry them: tasks, call activities, events, gateways, message flows, data object / data store references, lanes and participants (pools).
- Present means: a list with at least one item, a string that is not empty, or `draft: true`. `draft: false` and `deadline: none` count as absent, because they produce no attribute (section 3).
- Do not write an empty `ipd:trace`. Elements without any trace field have no `ipd:trace` and no trace text in `bpmn:documentation`.
- `bpmn:documentation` precedes `bpmn:extensionElements` (OMG BPMN 2.0 XSD, `tBaseElement` sequence).
- For pools, write the trace on `bpmn:participant`, not on the process.
- The viewer counts overlays as "elements with `ipd:source` children" (W1 gate: overlay count = elements with src).

## 5. Plain-text duplicate in `bpmn:documentation`

One `bpmn:documentation` element (`textFormat="text/plain"`) per traced element. One line per field, fixed order, line omitted if the field is empty, lines separated by `\n`:

```
Sources: <key> <loc> (p. <page>); <key> <loc>
Requirements: <REQ-id>, <REQ-id>
Binding: <binding>
Jurisdiction: <ICH|EU|US>, <...>
Deadline: <deadline>
Record: <record>
Party: <party>
Draft: DRAFT guidance
Verify: <item>; <item>
```

- ` (p. <page>)` only when `page` is given. `Draft: DRAFT guidance` only when `draft: true`.
- `Record:` and `Party:` come from the spec fields `record` and `party` (same values as the `ipd:trace` attributes).
- If a spec element also needs a free description later, it goes in a second `bpmn:documentation` after the trace text; the trace text is always the first one.

## 6. Example (task in model L4-01)

```xml
<bpmn:definitions xmlns:bpmn="http://www.omg.org/spec/BPMN/20100524/MODEL"
                  xmlns:ipd="urn:ipd-best-practice:trace:1.0"
                  id="IPD_DEFINITIONS" targetNamespace="urn:ipd-best-practice:model">
  <bpmn:process id="L4_01_P_SPON_PROCESS" isExecutable="false">
    <bpmn:task id="L4_01_A3" name="Notify regulatory authority">
      <bpmn:documentation textFormat="text/plain">Sources: EUCTR Art. 52(1) (p. printed 12 / PDF 14); E6R3 A1-3.12.2
Requirements: REQ-031
Binding: binding-law
Jurisdiction: EU
Deadline: 7 days
Record: notification record
Party: sponsor
Verify: [verify] page of E6R3 A1-3.12.2</bpmn:documentation>
      <bpmn:extensionElements>
        <ipd:trace binding="binding-law" jurisdiction="EU" deadline="7 days" record="notification record" party="sponsor">
          <ipd:source key="EUCTR" loc="Art. 52(1)" page="printed 12 / PDF 14" />
          <ipd:source key="E6R3" loc="A1-3.12.2" />
          <ipd:req id="REQ-031" />
          <ipd:verify>[verify] page of E6R3 A1-3.12.2</ipd:verify>
        </ipd:trace>
      </bpmn:extensionElements>
    </bpmn:task>
  </bpmn:process>
</bpmn:definitions>
```

The values in this example only illustrate the format; they are not findings.

## 7. Loading in bpmn-js / bpmn-moddle

```js
import ipdDescriptor from './contracts/ipd_moddle.json';
// bpmn-js
const viewer = new NavigatedViewer({ container, moddleExtensions: { ipd: ipdDescriptor } });
// bpmn-moddle
const moddle = new BpmnModdle({ ipd: ipdDescriptor });
const { rootElement, warnings } = await moddle.fromXML(xml);   // expect warnings.length === 0
```

Access: `bo.extensionElements.values.find(v => v.$type === 'ipd:Trace')` gives `binding`, `jurisdiction`, `deadline`, `draft`, `record`, `party`, `sources[]` (`key`, `loc`, `page`), `reqs[]` (`id`), `verifyItems[]` (`text`).

Descriptor notes:

- Types `Trace`, `Source`, `Req`, `Verify` map to tags `ipd:trace`, `ipd:source`, `ipd:req`, `ipd:verify` via `tagAlias: lowerCase`. Contained elements serialise by type name, so the property names `sources`, `reqs`, `verifyItems` never appear in XML.
- `ipd:req/@id` is a plain attribute, not an XML ID (`isId` not set), so the same REQ can sit on many elements without duplicate-ID errors.
- The descriptor was written without network access and is not yet runtime-tested. B2 must confirm zero import warnings and a lossless `fromXML` / `toXML` round trip; any fix is a contract change reported to the orchestrator.
